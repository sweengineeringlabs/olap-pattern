# ADR-003: Relationship to `database-cqrs-pattern`

**Status**: Proposed
**Date**: 2026-10-24
**Author**: edge platform engineering
**Relates to**: `database-cqrs-pattern` ADR-001, `oltp-pattern` ADR-003 and oltp-pattern#6, `edge-data`#10

## Context

`database-cqrs-pattern` (design discussion, no code yet) proposes a `query`
crate with entity-oriented read operations: `find` (by id), `list` (filter,
ordering, paging), `exists` and `count`, each with its own request, response
and error type. Its ADR notes that `query` looks close to `olap-pattern` for
list-style queries and asks whether it should extend, build on, or stay
separate from it.

`AnalyticalStore` is different in kind: it takes **declarative query text**
and streams back untyped rows, with no notion of an entity or an id.

## Decision (proposed)

- **Keep `AnalyticalStore` unchanged.** It stays the declarative-query contract.
- **Do not absorb the CQRS query side.** Entity-typed operations (`find`, `exists`, `count`) are a different abstraction from text queries, and the two have different consumers.
- **A CQRS query repository may be implemented on top of `AnalyticalStore`** by an adapter outside this repo. For example, `list` with a filter becomes a generated `SELECT`, and the rows become entities. The adapter owns query generation, so SQL injection handling and dialect differences are its responsibility, not this contract's.

## Alternatives considered

- **Extend `AnalyticalStore` with `find` / `exists` / `count`.** Rejected: it would add entity and id concepts to a contract that deliberately has none, and break `olap-svc`.
- **Make the CQRS `query` crate depend on `olap-pattern`.** Not decided here; that depends on whether `database-cqrs-pattern` wants a text-query dependency at all.

## Open questions

1. Does `database-cqrs-pattern`'s `query` side need streaming results? `AnalyticalStore` streams rows; a `find` returns one entity.
2. Should paging and ordering be part of `Query` (text) or generated by the adapter?
3. Who owns converting `Row` to a typed entity, given `ColumnValue` has only six primitive variants (see ADR-002)?

## Consequences

- No code change in this repo.
- `edge-data`#10 (query engine) and `database-cqrs-pattern` stay independent decisions that meet only at the adapter layer.
